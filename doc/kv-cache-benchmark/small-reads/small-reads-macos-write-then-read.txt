# Write-then-first-read (PageSpeed's alternate pattern), macOS (Apple M5), 2026-09-26.
# write_then_read.cpp: 4000 puts of 64 KiB into a 1 GiB volume (8 stripes); after
# put i, read back document i - lag (lag 1: just written; lag 1000: ~8 MiB per
# stripe behind the cursor, outside the 4 MiB recent-write window).  Every read is
# the first, CRC-pending read of a resident document.  cold_min 0 = both hints off.
# Five interleaved repetitions each.  The read-back is in write order, so it is a
# sequential run per stripe whose cursor moves on every read (a run chasing a
# writer); reads out of order are pinned by the unit tests.
