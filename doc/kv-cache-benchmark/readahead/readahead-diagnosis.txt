## Reading
- Cyclone and LMDB keep the same average number of reads in flight (~1.4), but LMDB's 126 KiB reads complete in
  73 us and Cyclone's (one ~508 KiB read plus one 4 KiB tail-page read per document) in 424 us on average.
- Only ~180 major faults per 4096 gets: the hint covers the content, and the header page is already cached as the
  tail page of the previous document in the same stripe. Faults are not the cost.
- The madvise call itself takes ~160 us: the kernel allocates, zeroes (clear_page_erms) and inserts
  (__add_to_page_cache_locked, xas_load) all 128 pages before it submits the read, so the device idles for that
  long per document. The checksum pass then waits ~410 us for the single large read, whose pages all unlock only
  when it completes. Nothing overlaps.
- The device itself reads a 512 KiB block of this file in 280-430 us with one read in flight, so the ~570 us
  per get is mostly idle device time plus serialisation, not bandwidth.
