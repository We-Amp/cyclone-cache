# TSan suppressions for Cyclone Cache
#
# See: https://github.com/google/sanitizers/wiki/ThreadSanitizerSuppressions
#
# Every entry here is a known false positive with a stated reason.  Nothing in
# this file covers a thread-teardown race: every Cache-owned thread (HitTracker
# flush, OptimizationEngine monitor, AdaptiveThreadPool workers,
# DirectorySyncer) is joined by Cache::stop() before the volumes are closed,
# so a report that touches ~Stripe, Volume::close or a worker loop is a real
# bug and must not be suppressed.

# MmapDirectory::probe vs clear/insert — seqlock-protected access that
# TSan cannot reason about (uses atomic seq + data fence pattern).
race:cyclone::MmapDirectory::probe
race:cyclone::MmapDirectory::clear
race:cyclone::MmapDirectory::insert

# In-memory Directory — same per-bucket seqlock pattern as MmapDirectory
# (readers copy raw DirEntry words between version loads + acquire fences;
# writers publish odd/even version transitions).  The reader side inlines
# into probe/probe_each callers, so suppress on the writer-side mutators
# (one matching frame in either stack suppresses the report) plus the
# reader entry points.
race:cyclone::Directory::probe
race:cyclone::Directory::probe_each
race:cyclone::Directory::insert
race:cyclone::Directory::remove
race:cyclone::Directory::remove_at
